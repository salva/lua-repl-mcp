Persistent Lua execution through MCP

Use Lua REPL MCP to keep working state between tool calls, compute explicit JSON results, or give a client access to an existing Lua application's APIs. This is static documentation, not a browser REPL or remote execution service.

Trusted code only: not a sandbox. Executed Lua has the process's full system privileges. Authorize access before running code; do not expose privileged hosts to untrusted clients. Printed output is not automatically captured.

What you can accomplish

  • Keep globals and functions between calls; send JSON inputs as Lua varargs.
  • Run independent managed sessions concurrently over one connection.
  • Start work asynchronously, then poll for a single-consumption result.
  • Embed without manager/native dependencies or a separate interpreter.
  • Recover from ordinary code errors without automatically losing prior state.

A call executes a complete Lua chunk once. Use return to produce results; there is no implicit expression evaluation. Top-level locals do not persist. Waiting is not execution: a wait timeout leaves work running, whereas a managed hard execution deadline, cancellation or kill destroys that session. Connection loss disposes of all its sessions; this is not durable storage.

Package status

The current source package is a development candidate, version 0.1.0-1, not a stable release. Known correctness and lifecycle issues are being repaired; independently validate important results and do not rely on it for production workloads yet. No public package-registry availability is claimed. The standalone target is Lua 5.4 on POSIX; the independent handler is pure Lua. See operations for resource defaults and lifecycle limitations.
